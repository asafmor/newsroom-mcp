# Change log

One row per shipped feature, newest last.

| Feature | Date | Summary | Details |
|---|---|---|---|
| merge-stories tool | 2026-09-02 | A ninth MCP tool that folds one active story into another when the agent realizes they're the same real-world event: items move over, timestamps reconcile, the loser is archived. | [merge-stories-tool.md](./merge-stories-tool.md) |
| GitHub releases provider | 2026-09-02 | Ingests GitHub release notes as primary-source content, so model and tool launches reach the desk without waiting for press coverage. | [github-releases-provider.md](./github-releases-provider.md) |
| Story development markers | 2026-09-03 | `get-feed` now reports each source's contribution, so the feed shows which reports moved a story forward instead of treating every source alike. | [story-development-markers.md](./story-development-markers.md) |
| Agent-assigned story topic tags | 2026-09-03 | The curating agent tags stories from a fixed ten-value vocabulary, surfaced through `get-feed` and `feed.json` with a client-side tag filter in the shared feed UI. | [story-topic-tags.md](./story-topic-tags.md) |
| get-story tool | 2026-09-03 | A tenth MCP tool that fetches one story by id, including archived stories and their complete attached-item history with `reason`, closing gaps `get-active-stories` and `get-feed` leave open. | [get-story-tool.md](./get-story-tool.md) |
| Locally-tracked read state | 2026-09-03 | Opening a story in the feed UI marks it read via `localStorage`; read cards are de-emphasized and the header shows an "N new" unread count, with no backend or `feed.json` change. | [story-read-state.md](./story-read-state.md) |
| Feed UI review findings | 2026-09-03 | Fixes four UI/UX review findings in the shared feed: the source detail is now a real keyboard modal, the mobile filter row recomposes instead of collapsing, card summaries are clamped to a scannable preview with the full text in the detail sheet, and freshness is calendar-aware with an explicit stale badge. | [ui-review-findings-feed.md](./ui-review-findings-feed.md) |
| Structured story summaries | 2026-09-03 | The curating agent can write an optional lede-plus-bullets shape inside `summary`, rendered as a real bullet list in both feed hosts; malformed or plain-prose summaries fall back to the original text unchanged. | [structured-story-summaries.md](./structured-story-summaries.md) |
| Per-story change deltas | 2026-09-04 | On a return visit, a story you've already opened shows what actually changed since then ("+2 sources, 1 new development") instead of an unchanging card, with the specific new sources and bullets tagged in the detail sheet; entirely client-side, no backend or `feed.json` change. | [story-change-deltas.md](./story-change-deltas.md) |
| Time-of-day theme | 2026-09-04 | Removed the light/dark/auto toggle from the feed UI; the app now picks the theme from the reader's local clock (dark 19:00–06:59, light 07:00–18:59), re-evaluating on load, on tab-visibility change, and at each boundary. | [time-of-day-theme.md](./time-of-day-theme.md) |
| Feed avatar overflow and desktop logo alignment | 2026-09-04 | A story card with exactly one hidden provider now shows that provider's real avatar instead of a generic "+1" circle (the caption stays numeric, since source names don't fit); the "+N" circle for 2+ is larger and actually centered; and deleting the app shell's doubled-up 24px desktop padding lets the header logo sit flush with the shell's left edge. | [feed-avatar-and-logo-bleed.md](./feed-avatar-and-logo-bleed.md) |
| Swipe to mark a story read | 2026-09-07 | On touch devices, swiping a story card left or right marks it read without opening it — either direction, never unread, card never removed from the list — while mouse/keyboard on desktop keep working exactly as before. | [swipe-to-mark-read.md](./swipe-to-mark-read.md) |
| Structured summary adoption | 2026-09-08 | The optional lede-plus-bullets convention had 0/50 adoption in production, so it is now the expected shape past ~280 characters, taught by a worked example and an `update-story` restructure trigger aimed at the accretion pathway that actually produces run-on summaries; `create-story`/`update-story` append a non-blocking advisory when a long summary lacks structure, and a read-only script measures adoption against a published snapshot. | [structured-summary-adoption.md](./structured-summary-adoption.md) |
| Weekly podcast digest | 2026-09-09 | A real, AI-narrated audio recap of the week's top stories, auto-published every Friday: the curating agent writes the script (two new MCP tools, one episode per ISO week enforced by SQLite), a fully mechanical GitHub Actions pipeline synthesizes it with OpenAI TTS, concatenates with ffmpeg, and hosts each episode as a GitHub Release asset (never committed to git) so history stays unbounded; playable with a full transcript on the standalone feed site. | [weekly-podcast-digest.md](./weekly-podcast-digest.md) |
| Podcast UI fixes | 2026-09-10 | Seven fixes against the weekly podcast digest: a status badge, tighter transcript-toggle spacing, playback-synced transcript highlighting, a card elevation treatment, a corrected covered-date range (derived from `publishedAt`, not the calendar ISO week), duration moved next to the week number, and — the significant one — audio hosting moved from GitHub Release assets to the `feed` branch's GitHub Pages site, fixing an iOS/WebKit playback failure caused by Releases' non-audio content type and `Content-Disposition: attachment`. | [podcast-ui-fixes.md](./podcast-ui-fixes.md) |
| Tool Radar | 2026-09-10 | A separate browse-oriented surface for trending AI tools, models and Hugging Face Spaces — deliberately not more stories in the news feed, since tooling is browsed and compared rather than skimmed. A weekly GitHub Action queries the GitHub Search API and Hugging Face's models/spaces endpoints, ranks and caps them deterministically, and publishes `tools.json` onto the `feed` branch; the site renders a card board with kind filters, snapshot-preserving bookmarks, and copy-to-clipboard install commands. Stateless by necessity, so there are deliberately no week-over-week deltas. | [tool-radar.md](./tool-radar.md) |
| Tool Radar UI follow-ups | 2026-09-10 | Fixes four reported issues against Tool Radar — a shared-avatar flex-shrink bug, a mismatched section background, verbose disclosure/explainer copy, and emoji icons — and redesigns the top entry-point bar after a UI/UX consultation: it moves below the header as a two-line band, which required scoping `.app-shell`/`.scroll-area`'s trapped `overflow` to the MCP View and using `overflow: clip` on the standalone site so `position: sticky` genuinely engages there. | [tool-radar-ui-followups.md](./tool-radar-ui-followups.md) |
